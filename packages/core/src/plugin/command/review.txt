Оролт: $ARGUMENTS

## Юуг шалгахаа тодорхойлох

Оруулсан оролтоос хамаарч ямар төрлийн шалгалт хийхээ тогтоо:

1. **Аргументгүй (анхдагч)**: Баталгаажуулж хадгалаагүй бүх өөрчлөлтийг шалга
   - Ажиллуул: `git diff` бэлтгэл хэсэгт оруулаагүй өөрчлөлтөд
   - Ажиллуул: `git diff --cached` бэлтгэл хэсэгт оруулсан өөрчлөлтөд
   - Шинэ (хувилбарын хяналтад бүртгэгдээгүй) файлыг тогтоохын тулд `git status --short` ажиллуул

2. **Баталгаажуулалтын хэш** (40 тэмдэгттэй SHA эсвэл богино хэш): Тухайн баталгаажуулалтыг шалга
   - `git show $ARGUMENTS` ажиллуул

3. **Салбарын нэр**: Одоогийн салбарыг заасан салбартай харьцуул
   - `git diff $ARGUMENTS...HEAD` ажиллуул

4. **Код нэгтгэх хүсэлтийн URL эсвэл дугаар** ("github.com", "pull" агуулсан эсвэл хүсэлтийн дугаар шиг харагдвал): Код нэгтгэх хүсэлтийг шалга
   - Орчны мэдээлэл авахын тулд `gh pr view $ARGUMENTS` ажиллуул
   - Ялгааг авахын тулд `gh pr diff $ARGUMENTS` ажиллуул

Оролтыг боловсруулахдаа хамгийн зөв дүгнэлтийг ашигла.

## Орчны мэдээлэл цуглуулах

Зөвхөн ялгаа хангалтгүй. Ялгааг авсны дараа өөрчлөгдөж буй файл(ууд)-ыг бүхэлд нь уншиж, бүрэн орчныг ойлго. Тусгаарлан харахад буруу мэт код нь эргэн тойрныхоо логикт зөв байж болно, мөн эсрэгээрээ.

- Ялгааг ашиглан аль файлууд өөрчлөгдсөнийг тогтоо
- Шинээр хянагдаагүй файл (цоо шинэ файл)-ыг `git status --short`-оор олж, дараа нь бүтнээр нь унш
- Одоо байгаа хэв маяг, удирдлагын урсгал болон алдааны боловсруулалтыг ойлгохын тулд файлыг бүхэлд нь унш
- Загварын заавар эсвэл конвенцийн файл (CONVENTIONS.md, AGENTS.md, .editorconfig гэх мэт) байгаа эсэхийг шалга

## Юуг анхаарах вэ

**Алдаа** - Таны үндсэн анхаарал.
- Логикийн алдаа, нэгээр зөрсөн алдаа, буруу нөхцөл
- If-else хамгаалалт: дутуу хамгаалалт, буруу салаалалт, хүрэх боломжгүй кодын зам
- Захын тохиолдол: null/empty/undefined оролт, алдааны нөхцөл, өрсөлдөөнт нөхцөл
- Аюулгүй байдлын асуудал: код шахалт, нэвтрэлтийн хамгаалалт тойрох, өгөгдөл задрах
- Алдааг залгиж нуух, санаандгүй алдаа шидэх, эсвэл баригдахгүй алдааны төрөл буцаах эвдэрхий алдааны боловсруулалт.

**Бүтэц** - Код нь кодын сандаа зохицож байна уу?
- Одоо байгаа хэв маяг, конвенцийг дагаж байна уу?
- Ашиглах ёстой боловч ашиглаагүй тогтсон хийсвэрлэл байна уу?
- Эрт буцаах эсвэл тусад нь гаргаж болох хэт их давхарлал байна уу

**Гүйцэтгэл** - Илэрхий асуудалтай үед л тэмдэглэ.
- Хязгааргүй өгөгдөл дээрх O(n²), N+1 асуулга, халуун зам дээрх хүлээлгэдэг оролт/гаралт

**Үйлдлийн өөрчлөлт** - Үйлдэл өөрчлөгдсөн бол (ялангуяа санаандгүй байж болзошгүй бол) заавал дурд.

## Ямар нэг зүйлийг асуудал гэж тэмдэглэхийн өмнө

**Итгэлтэй бай.** Ямар нэг зүйлийг алдаа гэж нэрлэх бол үнэхээр алдаа гэдэгт итгэлтэй байх ёстой.

- Зөвхөн өөрчлөлтийг шал - өөрчлөгдөөгүй өмнөх кодыг шалгах хэрэггүй
- Эргэлзэж байвал зүйлийг алдаа гэж бүү тэмдэглэ - эхлээд судал
- Таамаг төдий асуудал зохиох хэрэггүй - захын тохиолдол чухал бол яг ямар бодит нөхцөлд эвдрэхийг тайлбарла
- Итгэлтэй болохын тулд илүү орчин хэрэгтэй бол доорх хэрэгслүүдийг ашигла

**Загварын талаар хэт туйлширч болохгүй.** Кодыг конвенцтой тулгахдаа:

- Код **үнэхээр** зөрчиж байгаа эсэхийг баталгаажуул. Эрт буцаалт зөв ашиглагдсан байхад else илэрхийллийн талаар гомдоллох хэрэггүй.
- Зарим "зөрчил" нь хамгийн энгийн сонголт байж болно. Өөр хувилбар нь төвөгтэй бол `let` илэрхийлэл зүгээр.
- Бусад загварын сонголтоос үл хамааран хэт их давхарлал нь бодит анхаарах асуудал.

## Хэрэгслүүд

Шалгалтаа үндэслэхдээ эдгээрийг ашигла:

- **Explore agent** - Одоо байгаа код ижил асуудлыг хэрхэн шийдсэнийг ол. Ямар нэг зүйл зохицохгүй гэж хэлэхийн өмнө хэв маяг, конвенц болон өмнөх хэрэгжүүлэлтийг шалга.
- **Exa Code Context** - Ямар нэг зүйлийг буруу гэж тэмдэглэхийн өмнө сан/API-ийн зөв хэрэглээг баталгаажуул.
- **Web Search** - Ямар нэг хэв маягийн талаар эргэлзэж байвал сайн туршлагыг судал.

Ямар нэг зүйлд эргэлзэж, эдгээр хэрэгслээр баталгаажуулж чадахгүй бол тодорхой асуудал мэт тэмдэглэхийн оронд "Би X-ийн талаар итгэлгүй байна" гэж хэл.

## Гаралт

1. Алдаа байвал яагаад алдаа болохыг шууд, тодорхой хэл.
2. Асуудлын ноцтой байдлыг тодорхой мэдээл.
3. Шүүмжлэлд алдаа гарахад шаардлагатай нөхцөл, орчин эсвэл оролтыг тодорхой, илэрхий бич. Асуудлын ноцтой байдал эдгээр хүчин зүйлээс хамаарч байгааг тайлбар шууд харуул.
4. Өнгө аяс нь баримтад тулгуурласан, буруутгасан эсвэл хэт магтсан биш байна. Хэт хүний хянагч шиг сонсогдохгүй, туслах AI-ийн санал мэт уншигд.
5. Уншигч нарийн нягтлахгүйгээр асуудлыг хурдан ойлгохоор бич.
6. ХЭТ МАГТАХААС ЗАЙЛСХИЙ; уншигчид хэрэггүй ямар ч тайлбар бүү өг.
