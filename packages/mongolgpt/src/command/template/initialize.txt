Энэ repository-д зориулсан `AGENTS.md` файлыг үүсгэх эсвэл шинэчил.

Зорилго нь MongolGPT-ийн дараагийн ажиллагаанууд алдаа гаргалгүй, төслийг хурдан ойлгоход туслах товч зааврын файл үүсгэх. Мөр бүр "Тусламжгүй бол агент үүнийг анзаарахгүй өнгөрөх магадлалтай юу?" гэсэн асуултад хариулах ёстой. Үгүй бол бүү оруул.

Хэрэглэгчийн өгсөн анхаарах зүйл эсвэл хязгаарлалт (заавал мөрдөнө):
$ARGUMENTS

## Хэрхэн судлах вэ

Хамгийн их мэдээлэлтэй эх сурвалжийг эхэлж унш:
- `README*`, root manifest, workspace config, lockfile
- build, test, lint, formatter, typecheck, codegen config
- CI workflow болон pre-commit / task runner config
- одоо байгаа зааврын файл (`AGENTS.md`, `CLAUDE.md`, `.cursor/rules/`, `.cursorrules`, `.github/copilot-instructions.md`)
- `mongolgpt.json` зэрэг repository доторх MongolGPT config

Config болон docs-ийг уншсаны дараа архитектур тодорхойгүй хэвээр байвал бодит entrypoint, package-ийн зааг, ажиллах урсгалыг олохын тулд төлөөлөх цөөн кодын файлыг шалга. Санамсаргүй захын файлаас илүү системийн хэсгүүд хэрхэн холбогдсоныг тайлбарлах файлыг түрүүлж унш.

Ердийн тайлбар бичвэрээс илүү ажиллуулж шалгаж болох эх сурвалжийг үнэн зөвийн үндэс болго. Docs нь config эсвэл script-тэй зөрчилдвөл ажиллуулж болох эх сурвалжид итгэж, зөвхөн баталж чадсан мэдээллээ үлдээ.

## Ямар мэдээлэл гаргаж авах вэ

Энэ repository-д ажиллах агентын хувьд хамгийн хэрэгтэй баримтыг ол:
- хөгжүүлэгчийн яг ажиллуулах command, ялангуяа шууд ойлгомжгүй command
- нэг test, нэг package, эсвэл төвлөрсөн verification алхмыг хэрхэн ажиллуулах
- дараалал чухал үед мөрдөх command-ийн дараалал, жишээ нь `lint -> typecheck -> test`
- monorepo эсвэл олон package-ийн зааг, үндсэн хавтасны эзэмшил, бодит app/library entrypoint
- framework эсвэл toolchain-ийн онцлог: generated code, migration, codegen, build artifact, тусгай env ачаалалт, dev server, infra deploy урсгал
- үндсэн тохиргооноос ялгаатай, зөвхөн энэ repository-д мөрдөх style эсвэл workflow convention
- test-ийн онцлог: fixture, integration test-ийн урьдчилсан нөхцөл, snapshot workflow, шаардлагатай service, тогтворгүй эсвэл өндөр өртөгтэй suite
- одоо байгаа зааврын файлаас хадгалах шаардлагатай чухал хязгаарлалт

Сайн `AGENTS.md`-ийн агуулга нь ихэвчлэн хэд хэдэн файл уншиж байж ойлгох, амархан харагддаггүй нөхцөл байдаг.

## Асуулт

Repository-оос чухал мэдээллийн хариуг олж чадахгүй үед л хэрэглэгчээс асуу. `question` хэрэгслээр хамгийн ихдээ нэг богино багц асуулт асууна.

Зөв асуултын жишээ:
- баримтжуулаагүй багийн convention
- branch / PR / release-ийн хүлээлт
- мэдэгдэж байгаа боловч бичээгүй setup эсвэл test-ийн урьдчилсан нөхцөл

Repository-оос тодорхой харагдаж буй зүйлийг бүү асуу.

## Бичих дүрэм

Зөвхөн энэ repository-д хамаарах, хэрэгтэй мэдээллийг оруул. Жишээ нь:
- агент тааж буруу хийх магадлалтай яг command болон shortcut
- файлын нэрээс шууд ойлгогдохгүй архитектурын тэмдэглэл
- хэл эсвэл framework-ийн үндсэн тохиргооноос ялгаатай convention
- setup шаардлага, environment-ийн онцлог, ажиллагааны анхаарах зүйл
- одоо байгаа чухал зааврын эх сурвалжийн холбоос

Бүү оруул:
- ерөнхий software зөвлөгөө
- урт tutorial эсвэл файлын бүрэн мод
- ойлгомжтой хэлний convention
- таамагласан мэдэгдэл эсвэл баталж чадаагүй зүйл
- `mongolgpt.json`-ийн `instructions`-ээр заасан өөр файлд хадгалахад илүү тохиромжтой агуулга

Эргэлзэж байвал бүү оруул.

Богино хэсэг, жагсаалт ашигла. Repository энгийн бол файлыг энгийн байлга. Том бол агентын ажиллах аргад бодитоор нөлөөлөх цөөн бүтцийн баримтыг л хураангуйл.

`${path}` байршилд `AGENTS.md` аль хэдийн байвал сохроор дахин бичихийн оронд байранд нь сайжруул. Баталгаажсан хэрэгтэй зааврыг хадгалж, хэрэггүй эсвэл хуучирсан мэдээллийг устган, одоогийн кодын сантай нийцүүл.

Тайлбарыг монгол хэлээр бич. Command, file path, code identifier болон техникийн нэрийг эх хэлбэрээр нь хадгал.
