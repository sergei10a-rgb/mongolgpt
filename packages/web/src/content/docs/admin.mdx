Админ орчин нь хэрэглэгчийн өдөр тутмын чат орчин биш. Зөвхөн эрх олгогдсон оператор нэвтэрч системийн төлөв, хэрэглэгч, төлбөр болон аудитын мэдээллийг шалгана.

## Нэвтрэлт ба эрх

Админы домэйн нь Cloudflare Access болон олон хүчин зүйлийн баталгаажуулалт (MFA)-аар хамгаалагдсан байх ёстой. Үүний дараа аппын түвшний үүрэгт суурилсан хандалтын хяналт (RBAC) нь админы таних тэмдэг, үүрэг, зөвшөөрлийг дахин шалгана. Нэг операторт шаардлагагүй өргөн эрх олгохгүй. Админы нэвтрэх мэдээлэл, Access токен, сессийн дэлгэцийн зургийг нийтэд бүү хуваалц.

## Оператор нэмэх дараалал

Cloudflare Access-ийн зөвшөөрөл болон D1 дэх дотоод эрхийн бүртгэл хоёулаа хүчинтэй байж оператор нэвтэрнэ. Шинэ операторыг дараах дарааллаар нэмнэ:

1. Имэйлийг GitHub орчны `MONGOLGPT_ADMIN_BOOTSTRAP_EMAILS` нууц утгад жижиг үсгээр нэмнэ.
2. Админ орчныг байршуулж, Cloudflare Access бодлогод уг имэйл орсон болон MFA шаардаж байгааг шалгана.
3. Админы `Операторын удирдлага` хэсгээс хэрэгцээнд нь тохирсон хамгийн бага дотоод эрхээр операторыг нэмнэ.
4. Оператор Cloudflare Access-ийн MFA нэвтрэлт хийсний дараа апп Access хэрэглэгчийн таних тэмдгийг тухайн бүртгэлтэй холбоно.

Админы дэлгэц нь одоогийн зөвшөөрөгдсөн жагсаалтад байхгүй имэйлийг шинээр нэмэх эсвэл дахин идэвхжүүлэхийг алдаанд хаалттайгаар хориглоно. `Cloudflare хандалт` баганад `Жагсаалтад алга` гэж харагдвал эхлээд нууц утгыг шинэчилж админ орчныг дахин байршуулна. Операторыг бүрмөсөн хасахдаа эхлээд D1 дэх эрхийг түдгэлзүүлж, дараа нь нууц утгаас имэйлийг устгаад дахин байршуулна. Үйлдвэрлэлийн байршуулалт бүр тусдаа зөвшөөрөл шаарддаг.

## Одоогоор хийж болох зүйлс

Одоогийн хэрэгжилтэд эрхтэй админ хэрэглэгчийн жагсаалт, төлөв, түдгэлзүүлэх эсвэл дахин идэвхжүүлэх ажиллагаа, төлбөр ба хэрэглээний мэдээлэл, системийн бэлэн байдал, аудитын бүртгэлийг шалгаж чадна. Системийн бэлэн байдал нь runtime, OAuth, quota, queue, төлбөр, monitoring, D1 backup-аас гадна manifest дахь хувилбарын GitHub Release, checksum, Desktop updater metadata болон нийтийн npm багц бүрийг бодитоор тулгана. `payments.refund` эрхтэй админ баталгаажсан QPay subscription төлбөрт бүтэн буцаан олголт хийх эсвэл мөнгө буцаагдсан ч дотоод төлөв шинэчлэгдээгүй үед төлөв сэргээх ажиллагаа хийж чадна. Төлбөр, захиалгын үйл явдал, хэрэглээний хязгаарын тооцоо болон үйлчилгээ үзүүлэгчийн төлөвийг аудитын мөртэй тулгана.

## Одоогийн хязгаарлалт

Дараахыг бүрэн ажилладаг админы өөрчлөлт гэж бүү зарла:

- админы дэлгэцээс багц үүсгэх, унших, шинэчлэх, устгах (CRUD) болон бүх багцын хязгаарыг шууд өөрчлөх;
- захиалгыг дур мэдэн шилжүүлэх эсвэл засах;
- Bonum web нэхэмжлэхийн төлбөрийг баталгаажаагүй API-аар автоматаар буцаах;
- үйлчилгээ үзүүлэгчийн бэлэн байдал муудсан үед түүнийг бүх орчноос шууд засах эсвэл унтраах;
- хэрэглэгч бүрийн орлого болон нийт ашгийн хувийг бүрэн үйл ажиллагааны хянах самбараар харах.

Эдгээр нь одоогоор унших, тохируулах эсвэл операторын хяналт шаардсан хэсэг байж болно. Хэрэгжээгүй үйлдлийг UI-д амжилттай болсон мэт харуулах ёсгүй.

## Төлбөр ба хэрэглээний хяналт

Төлбөрийн үйл явдлыг нэхэмжлэх, мөнгөн дүн, валют, үйлчилгээ үзүүлэгчийн лавлагаа болон давхар боловсруулалтаас хамгаалах бүртгэлтэй тулгана. Захиалга идэвхжсэн эсэхийг зөвхөн гарын үсгээр баталгаажсан webhook эсвэл дарааллын үр дүнгээр шалгана. [Төлбөр, төлөвлөгөө ба хэрэглээ](../billing) болон [Cloudflare байршуулалт](../deployment)-ын туршилт, үйлдвэрлэлийн орчны ялгааг дагана.

QPay буцаалт нь зөвхөн серверийн хадгалсан нэхэмжлэхийн бүтэн дүнгээр хийгдэнэ. Админ дүн, валют, төлбөрийн дугаарыг гараар оруулахгүй. Буцаалтын үр дүн тодорхойгүй гэсэн анхааруулга гарвал шинэ буцаалт бүү үүсгэ; `QPay буцаалтыг шалгах` үйлдлээр үйлчилгээ үзүүлэгчийн төлвийг read-only шалгана. `Буцаалтын төлөв сэргээх` нь өмнө баталгаажсан буцаалтыг дахин мөнгө хөдөлгөхгүйгээр дотоод дараалалд оруулдаг.

## Аудит ба ослын ажиллагаа

Админы унших болон өөрчлөх үйлдэл аудитын бүртгэлд үлдэх ёстой. Сэжигтэй нэвтрэлт, нэвтрэх мэдээллийн алдагдал, хэрэглээний хязгаарыг зүй бусаар ашиглах оролдлого, webhook-ийн зөрүү илэрвэл хэрэглэгчийг түдгэлзүүлж, үйлчилгээ үзүүлэгчийн түлхүүрийг шинэчлэх эсвэл цуцлах, үйл явдлыг давхар боловсруулахгүйгээр бүртгэлүүдийг тулган нийцүүлэх дарааллыг баримтална.

`Үйлдлийн бүртгэл` хэсэг нь зөвхөн `audit.read` эрхтэй эзэмшигч болон ерөнхий админд харагдана. Админ имэйл, үйлдэл, зорилтын төрөл эсвэл ID, хүсэлтийн ID-аар хайж, амжилттай, татгалзсан, алдаатай үр дүнгээр шүүж болно. Бүртгэл өөрчлөх товчгүй бөгөөд дотоод metadata болон browser-ийн user-agent-ийг жагсаалтад задруулахгүй. Сэжигтэй мөрийг шалгахдаа хүсэлтийн ID, эх үүсвэрийн IP, огноог Cloudflare-ийн хамгаалалтын бүртгэлтэй тулгана.

Сэжигтэй үйл явдал болон тасалдлын үед [ослын хариу арга хэмжээ](../incident-response)-ний нэг эх сурвалж, severity, containment, evidence болон recovery дарааллыг дагана. Системийн алдааг [алдаа оношлох](../troubleshooting), нөөцлөлт ба сэргээх асуудлыг [нөөцлөлт ба сэргээх](../backup-restore), байршуулалт болон буцаалтыг [Cloudflare байршуулалт](../deployment) хуудаснаас үзнэ үү. Үйлдвэрлэлийн төлбөр, өгөгдлийн сангийн шилжилт, нэвтрэх мэдээллийн өөрчлөлт бүр тусдаа зөвшөөрөл болон урьдчилсан шалгалт шаарддаг.
