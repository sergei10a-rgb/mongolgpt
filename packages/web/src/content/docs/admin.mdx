Админ орчин нь хэрэглэгчийн өдөр тутмын чат орчин биш. Зөвхөн эрх олгогдсон оператор нэвтэрч системийн төлөв, хэрэглэгч, төлбөр болон аудитын мэдээллийг шалгана.

## Нэвтрэлт ба эрх

Админы домэйн нь Cloudflare Access болон MFA хамгаалалттай байх ёстой. Үүний дараа application-level RBAC нь админы subject, role, permission-ийг дахин шалгана. Нэг операторт шаардлагагүй өргөн эрх олгохгүй. Админы credential, Access token, session-ийн дэлгэцийн зургийг нийтэд бүү хуваалц.

## Одоогоор хийж болох зүйлс

Одоогийн хэрэгжилтэд эрхтэй админ хэрэглэгчид хэрэглэгчийн жагсаалт, хэрэглэгчийн төлөв, түдгэлзүүлэх/дахин идэвхжүүлэх, төлбөр/хэрэглээний унших мэдээлэл, системийн эрүүл мэнд болон аудитын бүртгэлийг шалгах боломжтой. Төлбөр, subscription event, quota settlement болон provider-ийн төлөвийг аудитын мөртэй тулгаж үзнэ.

## Одоогийн хязгаарлалт

Дараахыг бүрэн ажилладаг админы өөрчлөлт гэж бүү зарла:

- админы UI-гаас plan CRUD болон бүх төлөвлөгөөний лимитийг шууд өөрчлөх;
- subscription-ийг дур мэдэн шилжүүлэх эсвэл засах;
- QPay/Bonum-ийн буцаан олголтыг админы товчоор гүйцэтгэх;
- provider-ийн эрүүл мэнд муудсан үед provider-ийг бүх орчноос шууд засах/унтраах;
- хэрэглэгч бүрийн орлого болон нийт ашгийн хувийг бүрэн үйл ажиллагааны хянах самбараар харах.

Эдгээр нь одоогоор унших, тохируулах эсвэл операторын хяналт шаардсан хэсэг байж болно. Хэрэгжээгүй үйлдлийг UI-д амжилттай болсон мэт харуулах ёсгүй.

## Төлбөр ба хэрэглээний хяналт

Төлбөрийн event-ийг invoice, amount, currency, provider reference болон idempotency бүртгэлтэй тулгана. Subscription идэвхжсэн эсэхийг зөвхөн баталгаатай webhook/queue үр дүнгээр шалгана. [Төлбөр, төлөвлөгөө ба хэрэглээ](./billing) болон [Cloudflare байршуулалт](./deployment)-ын sandbox/production ялгааг дагана.

## Аудит ба ослын ажиллагаа

Админы унших болон өөрчлөх үйлдэл аудитын бүртгэлд үлдэх ёстой. Сэжигтэй нэвтрэлт, credential алдагдал, quota abuse, webhook-ийн зөрүү илэрвэл хэрэглэгчийг түдгэлзүүлэх, provider key-г rotate/revoke хийх, event-ийг дахин давхар боловсруулахгүйгээр reconciliation хийх дарааллыг баримтална.

Системийн алдааг [алдаа оношлох](./troubleshooting), backup/restore асуудлыг [backup ба сэргээх](./backup-restore), deploy болон rollback-ийг [Cloudflare байршуулалт](./deployment) хуудаснаас үзнэ үү. Production төлбөр, database migration, credential өөрчлөлт нь тусдаа зөвшөөрөл болон preflight шаарддаг.
