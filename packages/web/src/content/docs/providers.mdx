MongolGPT нь **75+ LLM үйлчилгээ үзүүлэгчийг** дэмжихийн тулд [AI SDK](https://ai-sdk.dev/) болон [Models.dev](https://models.dev) ашигладаг бөгөөд локал загвар ажиллуулахыг дэмждэг.

Нэгдсэн бүртгэлээр нэвтэрсэн хэрэглэгч үйлдвэрлэлийн үйлчилгээ идэвхтэй үед **MongolGPT Free Auto**-г ашиглана. Үүнээс гадна өөрийн үйлчилгээ үзүүлэгчийн API түлхүүр, OAuth эрх эсвэл локал API хаягийг хүссэн үедээ нэмж болно. Дэлгэрэнгүйг [бүртгэл, Free Auto ба багцын заавраас](../account) үзнэ үү.

:::caution
Free Auto болон төлбөртэй багцууд үйлдвэрлэлийн орчинд албан ёсоор нээгдтэл зөвхөн хөгжүүлэлтийн орчинд туршина. Туршилтын эсвэл хувь хүний үнэгүй API эрхийг нийтийн загварын гарц болгон ашиглахгүй.
:::

### Free Auto-ийн үйлчилгээний эрх

Free Auto-д MongolGPT-ийн удирддаг түлхүүрийг зөвхөн техникийн хувьд ажиллаж байгаагаар нь үйлдвэрлэлд зөвшөөрөхгүй. Нээлтийн өмнө үйлчилгээ үзүүлэгчийн тухайн үеийн албан ёсны нөхцөл, байгууллагын эрх болон хэрэглээний хязгаарыг дахин баталгаажуулна.

- [OpenRouter-ийн Free Models Router](https://openrouter.ai/docs/guides/routing/routers/free-router) нь туршилт, суралцах болон бага ачааллын хэрэглээнд зориулагдсан бөгөөд загварын бэлэн байдал, хүсэлтийн хязгаар нь өөрчлөгдөж болохыг анхааруулдаг. [OpenRouter FAQ](https://openrouter.ai/docs/faq)-д үнэгүй загваруудыг үйлдвэрлэлийн ачаалалд ерөнхийдөө тохиромжгүй гэж тайлбарласан. Иймээс байгууллагын тохирох эрх, зардлын хамгаалалт болон нээлтийн зөвшөөрөл баталгаажаагүй OpenRouter-ийн үнэгүй түлхүүрийг үйлдвэрлэлд ашиглахгүй.
- [NVIDIA API Trial Terms](https://assets.ngc.nvidia.com/products/api-catalog/legal/NVIDIA%20API%20Trial%20Terms%20of%20Service.pdf)-ийн дагуу API Catalog-ийн туршилтын эрх болон кредит нь дотоод туршилт, үнэлгээнд зориулагдсан. Үйлдвэрлэлийн хэрэглээнд NVIDIA эсвэл эрх бүхий үйлчилгээ үзүүлэгчийн тусдаа төлбөртэй эрх шаардлагатай. `build.nvidia.com`-оос авсан үнэгүй туршилтын түлхүүрийг MongolGPT-ийн нийтийн Free Auto нөөц чиглэл болгохгүй.
- NVIDIA-ийн нээлттэй загварын лиценз нь тухайн загварыг өөрийн дэд бүтцэд ажиллуулах эрх байж болох ч API Catalog-ийн туршилтын үйлчилгээг үйлдвэрлэлд ашиглах эрхтэй адил биш. Өөрийн дэд бүтцэд байршуулсан NIM эсвэл нээлттэй загвар ашиглах бол загвар, ажиллуулах орчин болон байршуулалтын лицензийг тус тус шалгана.

`productionUseApproved: true` гэдэг нь API ажилласныг биш, дээрх арилжааны эрх, нэвтрэх эрхийн төрөл, зардлын хязгаар болон операторын нээлтийн зөвшөөрөл бүгд баримтжсаныг илэрхийлнэ. Баталгаа дутуу бол үйлдвэрлэлийн урьдчилсан шалгалт тухайн чиглэлийг хаана.

Үйлчилгээ үзүүлэгч нэмэхийн тулд та:

1. `/connect` командыг ашиглан үйлчилгээ үзүүлэгчийн API түлхүүрүүдийг нэмнэ үү.
2. Өөрийн MongolGPT тохиргоонд үйлчилгээ үзүүлэгчийг тохируулна уу.

---

### Эрхийн мэдээлэл

Үйлчилгээ үзүүлэгчийн API түлхүүрүүдийг `/connect` командаар нэмэхэд дараах файлд хадгална:
`~/.local/share/mongolgpt/auth.json`

---

### Тохиргоо

Үйлчилгээ үзүүлэгчийн нарийвчилсан тохиргоог `mongolgpt.json` файлын `provider` хэсэгт өөрчилнө.

---

#### Үндсэн URL

Та `baseURL` сонголтыг тохируулснаар ямар ч үйлчилгээ үзүүлэгчийн URL суурийг өөрчлөх боломжтой. Энэ нь прокси үйлчилгээ эсвэл захиалгат төгсгөлийн цэгүүдийг ашиглахад хэрэгтэй.

```json title="mongolgpt.json" {6}
{
  "provider": {
    "anthropic": {
      "options": {
        "baseURL": "https://api.anthropic.com/v1"
      }
    }
  }
}
```

---

#### Загваруудыг нууж байна

Та `blacklist` сонголтыг ашиглан үйлчилгээ үзүүлэгчийн `/models` сонгогчоос тодорхой загваруудыг нууж болно. Энэ нь үйлчилгээ үзүүлэгч таны ашиглахыг эсвэл сонгохыг хүсэхгүй байгаа загваруудыг ил гаргахад хэрэгтэй.

```json title="mongolgpt.json" {6}
{
  "provider": {
    "anthropic": {
      "blacklist": ["claude-opus-4-20250514"]
    }
  }
}
```

Урвуу `whitelist` сонголт нь жагсаасан загваруудаас бусад бүх загварыг нуудаг.

```json title="mongolgpt.json" {6}
{
  "provider": {
    "anthropic": {
      "whitelist": ["claude-sonnet-4-20250514"]
    }
  }
}
```

Хоёр сонголт хоёулаа `/models` жагсаалтад харагдах загварын ID-уудын массив авна.

- `blacklist` жагсаасан загваруудыг сонгогчоос хасна.
- `whitelist` нь зөвхөн жагсаасан загваруудыг үлдээж, бусдыг нууна.
- Та тэдгээрийг нэгтгэж болно: `whitelist` багцыг нарийсгаж, дараа нь `blacklist` түүнээс оруулгуудыг устгана.

## MongolGPT бүртгэл ба Free Auto

Free Auto нь тусдаа API түлхүүр хуулж оруулах үйлчилгээ үзүүлэгч биш. Вэб, ширээний програм эсвэл CLI-д MongolGPT бүртгэлээр нэвтэрсний дараа загварын гарц үйлдвэрлэлийн орчинд идэвхтэй бол `mongolgpt/free-auto` загвар автоматаар бэлэн болно.

```bash
mongolgpt account login
```

Хязгаар, идэвхтэй багц болон ажлын талбараа `mongolgpt account open` командаар бүртгэлийн самбараас шалгана. Үйлдвэрлэлийн үйлчилгээ идэвхгүй үед Free Auto-г ажиллаж байгаа мэт харуулахгүй; BYOK эсвэл локал үйлчилгээ үзүүлэгч сонгоно.

### Бүртгэлдээ өөрийн түлхүүр холбох

Бүртгэлийн самбарын **Ажлын талбар → Өөрийн түлхүүрийг ашиглах** хэсгээс OpenAI, Anthropic, Google Gemini, OpenRouter эсвэл NVIDIA NIM түлхүүр нэмж болно. OpenRouter түлхүүр нэмбэл `mongolgpt/openrouter-byok`, NVIDIA NIM түлхүүр нэмбэл `mongolgpt/nvidia-nim-byok` загвар бэлэн болно.

Эдгээр түлхүүрийг түүхий текстээр хадгалахгүй. MongolGPT нь түлхүүрийг AES-GCM-ээр шифрлэж, тухайн ажлын талбар болон үйлчилгээ үзүүлэгчтэй холбон хадгална. Нийлүүлэгч рүү хүсэлт илгээх мөчид л сервер дотроо тайлж ашиглана. Түлхүүргүй үед BYOK чиглэлийг серверийн managed provider болгон ашиглахгүй.

Энэ нь төхөөрөмж дээрх `/connect` командаас тусдаа. `/connect`-оор нэмсэн түлхүүр тухайн төхөөрөмжийн `auth.json` файлд үлдэнэ; бүртгэлийн самбараар нэмсэн түлхүүр сонгосон ажлын талбарын гишүүдэд серверээр дамжин үйлчилнэ.

### Amazon Bedrock

Amazon Bedrock-г MongolGPT-тэй ашиглахын тулд:

1. Amazon Bedrock консолын **Загварын каталог** руу орж, ашиглахыг хүссэн загварууддаа хандах эрх хүснэ үү.

   :::tip
   Та Amazon Bedrock хаягаар хүссэн загвартаа хандах эрхтэй байх шаардлагатай.
   :::

2. Дараах аргуудын аль нэгээр **баталгаажуулалтаа тохируулна уу**:

   ***

   #### Орчны хувьсагчид (хурдан эхлүүлэх)

   mongolgpt ажиллуулж байх үед эдгээр орчны хувьсагчийн аль нэгийг тохируулна уу:

   ```bash
   # Сонголт 1: AWS access key ашиглах
   AWS_ACCESS_KEY_ID=XXX AWS_SECRET_ACCESS_KEY=YYY mongolgpt

   # Сонголт 2: Нэртэй AWS profile ашиглах
   AWS_PROFILE=my-profile mongolgpt

   # Сонголт 3: Bedrock Bearer токен ашиглах
   AWS_BEARER_TOKEN_BEDROCK=XXX mongolgpt
   ```

Эсвэл тэдгээрийг bash профайлдаа нэмнэ үү:

```bash title="~/.bash_profile"
export AWS_PROFILE=my-dev-profile
export AWS_REGION=us-east-1
```

---

#### Тохируулгын файл (санал болгосон)

Төсөлд зориулсан эсвэл байнгын тохиргооны хувьд `mongolgpt.json` ашиглана уу:

```json title="mongolgpt.json"
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1",
        "profile": "my-aws-profile"
      }
    }
  }
}
```

**Боломжтой сонголтууд:**

- `region` - AWS бүс (жишээ нь: `us-east-1`, `eu-west-1`)
- `profile` - `~/.aws/credentials` файл дахь AWS профайлын нэр
- `endpoint` - захиалгат VPC endpoint-ийн URL (`baseURL` сонголтын AWS-д зориулсан өөр нэр)

:::tip
Тохируулгын файлын сонголтууд нь орчны хувьсагчдаас давуу эрхтэй.
:::

---

#### Нарийвчилсан: VPC Төгсгөлийн цэгүүд

Хэрэв та Bedrock-д VPC төгсгөлийн цэгүүдийг ашиглаж байгаа бол:

```json title="mongolgpt.json"
{
  "provider": {
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1",
        "profile": "production",
        "endpoint": "https://bedrock-runtime.us-east-1.vpce-xxxxx.amazonaws.com"
      }
    }
  }
}
```

:::note
`endpoint` сонголт нь AWS-д зориулсан `baseURL` сонголтын өөр нэр юм. Хэрэв `endpoint` болон `baseURL` хоёуланг нь заасан бол `endpoint` давуу эрхтэй.
:::

---

#### Баталгаажуулах аргууд

- **`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`**: IAM хэрэглэгч үүсгэж, AWS консол дээр хандалтын түлхүүрүүдийг үүсгэнэ үү.
- **`AWS_PROFILE`**: `~/.aws/credentials` дахь нэрлэсэн профайлыг ашиглана. Эхлээд `aws configure --profile my-profile` эсвэл `aws sso login` ажиллуулна уу.
- **`AWS_BEARER_TOKEN_BEDROCK`**: Amazon Bedrock консолоос урт хугацааны API түлхүүр үүсгэнэ.
- **`AWS_WEB_IDENTITY_TOKEN_FILE` / `AWS_ROLE_ARN`**: EKS IRSA (үйлчилгээний дансны IAM үүрэг) эсвэл OIDC холбоо бүхий Kubernetes орчинд ашиглана. Үйлчилгээний дансны тэмдэглэгээ ашиглах үед эдгээр орчны хувьсагчийг Kubernetes автоматаар оруулдаг.

---

#### Баталгаажуулалтын давуу эрх

Amazon Bedrock дараах дарааллаар баталгаажуулна:

1.  **Bearer токен** - `AWS_BEARER_TOKEN_BEDROCK` орчны хувьсагч эсвэл `/connect` командаар оруулсан токен
2.  **AWS нэвтрэх мэдээллийн хэлхээ** - профайл, хандалтын түлхүүр, хуваалцсан нэвтрэх мэдээлэл, IAM үүрэг, web identity (EKS IRSA), instance metadata

:::note
Bearer токеныг `/connect` эсвэл `AWS_BEARER_TOKEN_BEDROCK`-ээр тохируулсан бол профайл зэрэг AWS-ийн бусад баталгаажуулалтын аргаас түрүүлж ашиглана.
:::

3. Хүссэн загвараа сонгохын тулд `/models` командыг ажиллуулна.

   ```txt
   /models
   ```

:::note
Захиалгат дүгнэлтийн профайл ашиглах бол загвар болон үйлчилгээ үзүүлэгчийн нэрийг түлхүүр болгон, `id` шинж чанарт ARN утгыг тохируулна уу. Ингэснээр зөв кэш ашиглагдана.
:::

```json title="mongolgpt.json"
{
  "provider": {
    "amazon-bedrock": {
      // ...
      "models": {
        "anthropic-claude-sonnet-4.5": {
          "id": "arn:aws:bedrock:us-east-1:xxx:application-inference-profile/yyy"
        }
      }
    }
  }
}
```

### Atomic Chat

Та `mongolgpt`-г [Atomic Chat](https://atomic.chat)-ээр дамжуулан локал загвар ашиглахаар тохируулж болно. Atomic Chat нь локал LLM-үүдийг OpenAI-тай нийцтэй API серверээр ажиллуулдаг ширээний програм юм (өгөгдмөл API хаяг: `http://127.0.0.1:1337/v1`).

```json title="mongolgpt.json" "atomic-chat" {5, 6, 8, 10-14}
{
  "provider": {
    "atomic-chat": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Atomic Chat (локал)",
      "options": {
        "baseURL": "http://127.0.0.1:1337/v1"
      },
      "models": {
        "<your-model-id>": {
          "name": "<your-model-name>"
        }
      }
    }
  }
}
```

Энэ жишээнд:

- `atomic-chat` нь захиалгат үйлчилгээ үзүүлэгчийн ID бөгөөд таны сонгосон дурын мөр байж болно.
- `npm` нь энэ үйлчилгээ үзүүлэгчийн ашиглах багцыг заана. Энд OpenAI-тай нийцтэй API-д `@ai-sdk/openai-compatible` ашиглаж байна.
- `name` нь интерфэйст харагдах үйлчилгээ үзүүлэгчийн нэр.
- `options.baseURL` нь дотоод серверийн API хаяг. Atomic Chat-ийн тохиргоонд тааруулан хост болон портыг өөрчилнө үү.
- `models` нь загварын ID болон интерфэйст харагдах нэрийн зураглал юм. ID бүр `GET /v1/models` хүсэлтийн буцаах `id`-тай таарч байх ёстой. Atomic Chat-д ачаалсан ID-уудыг харахын тулд `curl http://127.0.0.1:1337/v1/models` ажиллуулна уу.

:::tip

### DigitalOcean

DigitalOcean-ийн [Дүгнэлт хөдөлгүүр](https://docs.digitalocean.com/products/inference/) нь GPT-OSS, Llama, Qwen, болон DeepSeek зэрэг нээлттэй загваруудад хандах боломжийг олгодог бөгөөд хүсэлт бүрийг хамгийн хямд, хурдан эсвэл хамгийн тохиромжтой загвар руу чиглүүлдэг захиалгат [Дүгнэлт чиглүүлэгчид](https://docs.digitalocean.com/products/genai-platform/concepts/inference-routers/).

MongolGPT нь баталгаажуулалтын хоёр аргыг дэмждэг:

- **OAuth (Санал болгосон)** — DigitalOcean бүртгэлдээ нэвтэрнэ үү; MongolGPT нь таны DigitalOcean API жетоныг шууд дүгнэлт хийхэд ашиглаж, таны Inference Routers-ийг илрүүлдэг.
- **Загвар нэвтрэх түлхүүр** — DigitalOcean консолоос байгаа түлхүүрийг буулгана уу.

#### OAuth (Санал болгосон)

1. `/connect` командыг ажиллуулаад **DigitalOcean** гэж хайна уу.

   ```txt
   /connect
   ```

2. **DigitalOcean-р нэвтрэх**-г сонгоно уу.

   ```txt
   ┌ Баталгаажуулалтын аргыг сонгоно уу
   │
   │ DigitalOcean-оор нэвтрэх
   │ Model Access Key оруулах
   └
   ```

3. Таны хөтөч MongolGPT-д зөвшөөрөл олгохоор нээгдэнэ. Нэвтэрч, зөвшөөрнө үү.

   :::note
   MongolGPT нь `genai:read` болон `inference:query` OAuth эрхийн хүрээг хүснэ. Таны DigitalOcean API токеныг загвар ажиллуулахад шууд ашиглах тул тусдаа Model Access Key үүсэхгүй.
   :::

   :::note
   Дүгнэлт чиглүүлэгчид зөвхөн OAuth-ийн дараа загвар сонгогч дээр гарч ирнэ. Загварын хандалтын түлхүүрийг гараар буулгах нь чиглүүлэгчийг илрүүлэхгүй.
   :::

4. `/models` командыг ажиллуулна. Таны дүгнэлт чиглүүлэгчид загвар сонгоход `router:` форматаар харагдана.

   ```txt
   /models
   ```

5. Шинээр үүсгэсэн Дүгнэлт чиглүүлэгчийг авахын тулд `/connect`-г дахин ажиллуулаад **DigitalOcean**-г дахин сонгоно уу.

#### Model Access Key ашиглах

Хэрэв та түлхүүрээ шууд буулгахыг хүсвэл:

1. [DigitalOcean консол](https://cloud.digitalocean.com/)-ийн Дүгнэлт хэсгийн **Удирдах** хуудас руу орж шинэ түлхүүр үүсгэнэ үү.

   ```txt
   ┌ DigitalOcean Model Access Key-гээ оруулна уу
   │
   │
   └ Оруулах товчийг дарна уу
   ```

   :::note
   Дүгнэлт чиглүүлэгчийг энэ аргаар автоматаар илрүүлдэггүй. Тэдгээрийг загвар сонгогч дээр харуулахын тулд оронд нь OAuth-ээр нэвтэрнэ үү.

#### Дүгнэлтийн чиглүүлэгчид

Дүгнэлтийн чиглүүлэгч нь олон загварт зориулсан чиглүүлэлтийн бодлого тодорхойлно. Ингэснээр хүсэлт бүрийн даалгаварт үндэслэн хамгийн хямд, хурдан эсвэл тохиромжтой загварыг сонгож болно. OAuth нэвтрэлтийн дараа MongolGPT загвар сонгох жагсаалтад чиглүүлэгч бүрийг `router:<router-name>` хэлбэрээр харуулна.

Чиглүүлэгчийг бусад загвартай адил сонгоно. MongolGPT хүсэлтийг дамжуулахад DigitalOcean чиглүүлэгчийн бодлогоор бодит загварыг сонгоно. Дэлгэрэнгүйг [дүгнэлтийн чиглүүлэгчийн заавраас](https://docs.digitalocean.com/products/inference/how-to/use-inference-router/) үзнэ үү.

##### Өөрийн серверт байршуулсан GitLab-д OAuth тохируулах

OAuth ашиглахын тулд GitLab-ийн **Settings → Applications** хэсэгт шинэ application үүсгэнэ.

- `api` (таны өмнөөс API-д хандах)

Дараа нь application ID-г орчны хувьсагчаар өгнө:

##### GitLab Duo Agent Platform (DAP) ажлын урсгалын загварууд

DAP ажлын урсгалын загварууд нь хэрэгслийн дуудлагыг ердийн агентын чатаар бус,
GitLab-ийн Duo Workflow Service (DWS)-ээр дамжуулан ажиллуулах өөр гүйцэтгэлийн зам өгдөг.
`duo-workflow-*` загварыг сонгоход MongolGPT:

1. GitLab namespace-аас боломжтой загваруудыг илрүүлнэ.
2. Олон загвар байвал сонгох жагсаалт харуулна.
3. Дараагийн удаа хурдан эхлүүлэхийн тулд сонгосон загварыг дискэнд хадгална.
4. Хэрэгсэл ажиллуулах хүсэлтийг MongolGPT-ийн зөвшөөрлийн системээр дамжуулна.

Боломжтой DAP ажлын урсгалын загварууд `duo-workflow-*` нэршлийг дагадаг бөгөөд
таны GitLab instance-аас автоматаар илэрнэ.

#### Нэмэлт тохиргоо

Хэрэв та Helicone-ээс mongolgpt-р автоматаар тохируулагдаагүй функц эсвэл загварыг олж харвал та үүнийг хүссэн үедээ өөрөө тохируулах боломжтой.

Энд [Helicone загварын лавлах](https://helicone.ai/models), энэ нь нэмэхийг хүссэн загварынхаа ID-г авахын тулд танд хэрэгтэй болно.

```jsonc title="~/.config/mongolgpt/mongolgpt.jsonc"
{
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
      },
      "models": {
        "gpt-4o": {
          // Helicone-ийн загварын лавлах хуудсан дахь Model ID
          "name": "GPT-4o", // Model-д өгөх өөрийн нэр
        },
        "claude-sonnet-4-20250514": {
          "name": "Claude Sonnet 4",
        },
      },
    },
  },
}
```

#### Нэмэлт HTTP толгой хэсэг

Helicone нь кэш хийх, хэрэглэгчийг хянах, сессийг удирдах зэрэг функцүүдийн захиалгат толгой хэсгийг дэмждэг. Тэдгээрийг `options.headers` ашиглан үйлчилгээ үзүүлэгчийн тохиргоонд нэмнэ үү:

```jsonc title="~/.config/mongolgpt/mongolgpt.jsonc"
{
  "provider": {
    "helicone": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Helicone",
      "options": {
        "baseURL": "https://ai-gateway.helicone.ai",
        "headers": {
          "Helicone-Cache-Enabled": "true",
          "Helicone-User-Id": "mongolgpt",
        },
      },
    },
  },
}
```

##### Сеанс хянах

Helicone-ийн [Sessions](https://docs.helicone.ai/features/sessions) боломж нь холбоотой LLM хүсэлтүүдийг нэг сесс болгон бүлэглэнэ. MongolGPT-ийн яриа бүрийг Helicone-д автоматаар бүртгэхийн тулд локал Helicone сессийн залгаасыг ашиглана уу.

```bash
# MongolGPT-д зориулсан тусдаа npm залгаас хараахан нийтлэгдээгүй.
# Локал залгаасын файл ашиглах эсвэл холбогчийг дараах командаар импортолно:
mongolgpt compat import plan ./plugins/helicone-session.ts
```

Үүнийг өөрийн тохиргоонд нэмнэ үү.

```json title="mongolgpt.json"
{
  "plugin": ["./plugins/helicone-session.ts"]
}
```

Энэхүү залгаас нь таны хүсэлтэд `Helicone-Session-Id` болон `Helicone-Session-Name` толгойг оруулдаг. Helicone-ийн Sessions хуудсанд та MongolGPT харилцан яриа бүрийг тусдаа сесс хэлбэрээр жагсаасан харагдана.

##### Helicone-ийн түгээмэл HTTP толгой хэсгүүд

| Толгой                     | Тодорхойлолт                                                                |
| -------------------------- | --------------------------------------------------------------------------- |
| `Helicone-Cache-Enabled`   | Хариултын кэшийг идэвхжүүлэх (`true`/`false`)                               |
| `Helicone-User-Id`         | Хэрэглэгчийн хэмжүүрийг хянах                                               |
| `Helicone-Property-[Name]` | Захиалгат шинж чанаруудыг нэмэх (жишээ нь: `Helicone-Property-Environment`) |
| `Helicone-Prompt-Id`       | Хүсэлтийг шуурхай хувилбаруудтай холбох                                     |

Боломжтой бүх толгой хэсгийг [Helicone толгойн лавлах](https://docs.helicone.ai/helicone-headers/header-directory) харна уу.

   ```txt
   │ Snowflake-д гадаад хөтчөөр нэвтрэх
   │ PAT эсвэл Bearer токеныг гараар оруулах
   └
   ```

3. Сануулахад [данс танигч](https://docs.snowflake.com/en/user-guide/admin-account-identifier)-г оруулна уу, жишээ нь `myorg-myaccount` эсвэл `xy12345.us-east-1`.

   ```txt
   ┌ Snowflake бүртгэлийн танигч
   │
   │
   └ Оруулах товчийг дарна уу
   ```

4. Сонголтоор Snowflake role оруулна (жишээ нь `SYSADMIN`). Өгөгдмөл role ашиглах бол хоосон орхино.

5. Нээгдэх вэб хөтчөөр нэвтэрч дуусгана уу. MongolGPT OAuth буцаан дуудлагыг автоматаар барьж, токеныг хадгалдаг - хуулах/буулгах шаардлагагүй.

6. Загвар сонгохын тулд `/models` командыг ажиллуулна.

   ```txt
   /models
   ```

:::note
Хөтчийн OAuth урсгал нь Snowflake-ийн `SNOWFLAKE$LOCAL_APPLICATION` аюулгүй байдлын интеграцийг ([баримт бичиг](https://docs.snowflake.com/en/user-guide/oauth-local-applications)) ашигладаг. Энэ интеграци бүх бүртгэлд байдаггүй тул танай бүртгэлд байгаа эсэхийг дараах командаар шалгана уу:

```sql
SHOW SECURITY INTEGRATIONS LIKE 'SNOWFLAKE$LOCAL_APPLICATION';
```

Үр дүн хоосон байвал доорх **Bearer токеныг гараар оруулах** аргыг ашиглана уу.
:::

#### Bearer токеныг гараар оруулах

Хэрэв та токеныг шууд буулгахыг хүсч байвал эсвэл таны бүртгэлд `SNOWFLAKE$LOCAL_APPLICATION` байхгүй бол:

1. Snowflake дансандаа [Програмчлалын хандалтын токен (PAT)](https://docs.snowflake.com/en/user-guide/programmatic-access-tokens) үүсгэнэ үү.

2. `/connect` командыг ажиллуулж, **Snowflake Cortex** гэж хайгаад **Paste PAT эсвэл зөөгч токеныг гараар** сонгоно уу.

3. Сануулахад [данс танигч](https://docs.snowflake.com/en/user-guide/admin-account-identifier)-г оруулна уу.

4. PAT-г наа.

5. Загвар сонгохын тулд `/models` командыг ажиллуулна.

   ```txt
   /models
   ```

#### Орчны хувьсагч

```bash

export SNOWFLAKE_CORTEX_TOKEN=your-pat-or-jwt
```

:::note
`SNOWFLAKE_CORTEX_TOKEN` зөвхөн PAT эсвэл JWT-г хүлээн зөвшөөрдөг - хөтчийн OAuth урсгалыг зөвхөн `/connect`-р ашиглах боломжтой бөгөөд орчны хувьсагчаар дамжуулан тохируулах боломжгүй. `SNOWFLAKE_CORTEX_PAT` нь буцаад нийцтэй байхаар дэмжигдсэн хэвээр байна.
:::

## Захиалгат үйлчилгээ үзүүлэгч

`/connect` командын жагсаалтад ороогүй **OpenAI нийцтэй** үйлчилгээ үзүүлэгчийг нэмэхийн тулд:

:::tip
Та MongolGPT-тэй OpenAI-тай нийцтэй дурын үйлчилгээ үзүүлэгчийг ашиглаж болно. Орчин үеийн AI үйлчилгээ үзүүлэгчдийн ихэнх нь OpenAI-тай нийцтэй API санал болгодог.
:::

1. `/connect` командыг ажиллуулаад **Бусад** руу доош гүйлгэ.

   ```bash
   $ /connect

   ┌  Нэвтрэх мэдээлэл нэмэх
   │
   ◆  Үйлчилгээ үзүүлэгч сонгох
   │  ...
   │  ● Бусад
   └
   ```

2. Үйлчилгээ үзүүлэгчийн хувьд өвөрмөц ID оруулна уу.

   ```bash
   $ /connect

   ┌  Нэвтрэх мэдээлэл нэмэх
   │
   ◇  Үйлчилгээ үзүүлэгчийн ID оруулах
   │  myprovider
   └
   ```

   :::note
   Тохиргооны файлдаа дахин ашиглах тул мартахгүй, давтагдахгүй ID сонгоно уу.
   :::

3. Үйлчилгээ үзүүлэгчийн хувьд API түлхүүрээ оруулна уу.

   ```bash
   $ /connect

   ┌  Нэвтрэх мэдээлэл нэмэх
   │
   ▲  Энэ нь зөвхөн myprovider-ийн нэвтрэх мэдээллийг хадгална. Үйлчилгээ үзүүлэгчээ mongolgpt.json файлд тусад нь тохируулна; жишээг баримт бичгээс харна уу.
   │
   ◇  API түлхүүрээ оруулна уу
   │  sk-...
   └
   ```

4. Төслийн лавлахдаа `mongolgpt.json` файлаа үүсгэх буюу шинэчлэх:

   ```json title="mongolgpt.json" "myprovider" {5-15}
   {
     "provider": {
       "myprovider": {
         "npm": "@ai-sdk/openai-compatible",
         "name": "Миний AI үйлчилгээ үзүүлэгч",
         "options": {
           "baseURL": "https://api.myprovider.com/v1"
         },
         "models": {
           "my-model-name": {
             "name": "Миний загвар"
           }
         }
       }
     }
   }
   ```

   Энд тохиргооны сонголтууд байна:
   - **`npm`**: AI SDK-ийн ашиглах багц. OpenAI-тай нийцтэй `/v1/chat/completions` API хаягт `@ai-sdk/openai-compatible` ашиглана. Үйлчилгээ үзүүлэгч эсвэл загвар `/v1/responses` ашигладаг бол `@ai-sdk/openai` сонгоно.
   - **`name`**: Интерфэйст харагдах нэр.
   - **`models`**: Ашиглах боломжтой загварууд.
   - **`options.baseURL`**: API хаягийн URL.
   - **`options.apiKey`**: Нэвтрэх мэдээллийн сан ашиглаагүй үед API түлхүүрийг тохируулна.
   - **`options.headers`**: Нэмэлт HTTP толгой хэсгүүдийг тохируулна.

   Доорх жишээн дээрх дэвшилтэт сонголтуудын талаар дэлгэрэнгүй үзнэ үү.

5. `/models` командыг ажиллуулснаар таны захиалгат үйлчилгээ үзүүлэгч болон загварууд сонголтын жагсаалтад гарч ирнэ.

---

##### Жишээ

`apiKey`, `headers`, загвар `limit` сонголтуудыг тохируулах жишээ энд байна.

```json title="mongolgpt.json" {9,11,17-20}
{
  "provider": {
    "myprovider": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Миний AI үйлчилгээ үзүүлэгч",
      "options": {
        "baseURL": "https://api.myprovider.com/v1",
        "apiKey": "{env:ANTHROPIC_API_KEY}",
        "headers": {
          "Authorization": "Bearer custom-token"
        }
      },
      "models": {
        "my-model-name": {
          "name": "Миний загвар",
          "limit": {
            "context": 200000,
            "output": 65536
          }
        }
      }
    }
  }
}
```

Тохиргооны дэлгэрэнгүй:

- **`apiKey`**: [Орчны хувьсагчийн бичлэгийн дүрэм](../config#орчны-хувьсагчид) ашиглан тохируулна.
- **`headers`**: Хүсэлт бүртэй хамт нэмэлт HTTP толгой хэсэг илгээнэ.
- **`limit.context`**: Загвар хүлээн авах оролтын токены дээд хэмжээ.
- **`limit.output`**: Загварын үүсгэх гаралтын токены дээд хэмжээ.

`limit` талбарууд нь MongolGPT танд хэр их контекст үлдээснийг ойлгох боломжийг олгодог. Стандарт үйлчилгээ үзүүлэгчид эдгээрийг models.dev-ээс автоматаар татдаг.

## Алдааг олж засварлах

Үйлчилгээ үзүүлэгчийг тохируулахад асуудал гарвал дараах зүйлсийг шалгана уу.

1. **Нэвтрэх тохиргоог шалгах**: `mongolgpt providers list` ажиллуулж, үйлчилгээ үзүүлэгчийн нэвтрэх мэдээлэл бүртгэгдсэн эсэхийг шалгана.

   Энэ нь баталгаажуулалтдаа орчны хувьсагчдаас хамаардаг Amazon Bedrock зэрэг үйлчилгээ үзүүлэгчдэд хамаарахгүй.

2. **Захиалгат үйлчилгээ үзүүлэгчийн тохиргоог шалгах**:
   - `/connect` командад ашигласан үйлчилгээ үзүүлэгчийн ID нь `mongolgpt.json` дахь ID-тай таарч байгаа эсэхийг шалгана.
   - Үйлчилгээ үзүүлэгчдээ зөв `npm` багц сонгосон эсэхийг шалгана. Жишээлбэл, Cerebras-д `@ai-sdk/cerebras` ашиглана. OpenAI-тай нийцтэй `/v1/chat/completions` API хаягт `@ai-sdk/openai-compatible`, `/v1/responses` API хаягт `@ai-sdk/openai` ашиглана. Нэг үйлчилгээ үзүүлэгчийн загварууд өөр өөр протокол ашигладаг бол загвар бүрийн `npm` утгыг тусад нь тохируулж болно.
   - `options.baseURL` талбарт зөв API хаяг оруулсан эсэхийг шалгана.
