MongolGPT-ийн веб бүтээгдэхүүний байршуулалтын үндсэн платформ нь **Cloudflare**. Vercel болон Supabase нь launch архитектурын сонголт биш.

OpenRouter, NVIDIA NIM, Bonum болон QPay нь хиймэл оюуны загвар, төлбөрийн гадаад API болохоос MongolGPT-ийн hosting платформ биш.

:::caution
Hosted орчны үндсэн өгөгдөл D1, quota болон rate limit нь SQLite-backed Durable Objects, өндөр ачааллын usage бичилт нь Queues ашиглана. Production deploy нээлттэй боловч OAuth, model provider болон domain-ийн бодит нууц утгыг тохируулж, `deploy:preflight` болон smoke шалгалтыг заавал давуулна.
:::

## Үйлчилгээний хаягууд

Production domain-ийг `mgpt.mn` гэж үзвэл:

| Үйлчилгээ             | Хаяг                        |
| --------------------- | --------------------------- |
| Account болон Console | `https://mgpt.mn`           |
| Web app               | `https://app.mgpt.mn`       |
| Монгол баримт бичиг   | `https://docs.mgpt.mn/docs` |
| OAuth үйлчилгээ       | `https://auth.mgpt.mn`      |
| QPay + Bonum төлбөр   | `https://pay.mgpt.mn`       |
| Админ удирдлага       | `https://admin.mgpt.mn`     |
| Sync API (сонголттой) | `https://api.mgpt.mn`       |

`dev` орчинд эдгээрийн domain-ийн өмнө `dev.` нэмэгдэнэ. Жишээ нь `https://app.dev.mgpt.mn`.

`api.<domain>` нь үндсэн launch үйлчилгээ биш. Зөвхөн `MONGOLGPT_ENABLE_SYNC_SERVICE=true` үед нэмэлт sync service-тэй хамт байршуулна.

## Cloudflare бүтэц

| Хэсэг                        | Cloudflare үйлчилгээ             |
| ---------------------------- | -------------------------------- |
| Баримт бичиг                 | Astro Worker                     |
| Web app                      | Static Assets / Worker           |
| Console ба Free Auto gateway | SolidStart Worker                |
| OAuth                        | Worker + KV                      |
| QPay + Bonum gateway         | Worker + Queue + D1              |
| Админ хамгаалалт             | Cloudflare Access + MFA          |
| Үндсэн өгөгдөл               | D1                               |
| Token quota, атомик тоолуур  | SQLite-backed Durable Objects    |
| Өндөр ачааллын usage бичилт  | Queues + dead-letter Queue + D1  |
| Бодит цагийн статистик       | Cloudflare D1 + `stats.<domain>` |
| Мэдээллийн захидлын бүртгэл  | Cloudflare D1                    |
| Enterprise холбогдох хүсэлт  | Cloudflare D1                    |

KV нь нэг key-д олон зэрэгцээ бичилт шаарддаг token болон төлбөрийн тоолуурт ашиглагдахгүй. Ийм төлөвийг Durable Objects сериал дарааллаар удирдана.

## Deploy-оос өмнөх шалгалт

Repository-ийн үндсэн хавтаснаас:

```powershell
$env:MONGOLGPT_DOMAIN="mgpt.mn"
$env:CLOUDFLARE_DEFAULT_ACCOUNT_ID="<account-id>"
$env:CLOUDFLARE_API_TOKEN="<api-token>"
bun run deploy:preflight -- dev
```

Static dev staging байрлуулах:

```powershell
$env:MONGOLGPT_ENABLE_HOSTED_SERVICES="false"
bun sst deploy --stage=dev
bun run deploy:smoke -- dev
```

Production deploy хийхэд нэмэлт баталгаажуулалт заавал өгнө:

```powershell
$env:MONGOLGPT_PRODUCTION_CONFIRMATION="DEPLOY mgpt.mn"
bun run deploy:preflight -- production
```

## GitHub тохиргоо

Cloudflare Dashboard хэвийн болмогц GitHub repository-ийн `Settings` → `Secrets and variables` → `Actions` хэсэгт дараахыг тохируулна.

Repository түвшинд Cloudflare-ийн нийтлэг тохиргоог хадгална.

| Төрөл    | Нэр                             | Утга                                       |
| -------- | ------------------------------- | ------------------------------------------ |
| Variable | `MONGOLGPT_DOMAIN`              | `mgpt.mn`                                  |
| Variable | `CLOUDFLARE_DEFAULT_ACCOUNT_ID` | Cloudflare account ID                      |
| Secret   | `CLOUDFLARE_API_TOKEN`          | Хамгийн бага шаардлагатай эрхтэй API token |

`dev` болон `production` GitHub Environment тус бүрд өөрийн OAuth, session болон model credential хадгална.

| Төрөл    | Нэр                              | Утга                                                                 |
| -------- | -------------------------------- | -------------------------------------------------------------------- |
| Variable | `MONGOLGPT_AUTH_EMAIL_DOMAINS`   | Dev-д зөвшөөрөх яг email эсвэл domain; таслалаар тусгаарлана         |
| Variable | `GITHUB_CLIENT_ID_CONSOLE`       | Тухайн environment-ийн GitHub OAuth App client ID                    |
| Variable | `GOOGLE_CLIENT_ID`               | Тухайн environment-ийн Google Web OAuth client ID                    |
| Variable | `MONGOLGPT_PAYMENT_PLAN_CATALOG` | Basic/Pro/Max багцын MNT үнэ, Монгол нэр бүхий JSON                  |
| Secret   | `GITHUB_CLIENT_SECRET_CONSOLE`   | GitHub OAuth App client secret                                       |
| Secret   | `BYOK_CREDENTIALS_KEY_V1`        | 32+ тэмдэгт тогтвортой CSPRNG key; rotation хийх хүртэл солихгүй     |
| Secret   | `MONGOLGPT_RUNTIME_SECRET`       | 32+ тэмдэгт Cloudflare Sandbox account-isolation secret              |
| Secret   | `MONGOLGPT_PLAN_LIMITS`          | Free/Basic/Pro/Max plan, token, cost болон rate-limit JSON           |
| Secret   | `ZEN_SESSION_SECRET`             | 32+ тэмдэгт тусдаа CSPRNG session secret                             |
| Secret   | `ZEN_MODELS1`                    | Баталгаажсан Free Auto model/provider JSON; provider key-ийг агуулна |
| Secret   | `ZEN_MODELS2`…`ZEN_MODELS30`     | `ZEN_MODELS1` багтахгүй үед JSON-ийн дараалсан optional хэсгүүд      |

QPay + Bonum sandbox төлбөр асаах environment-д дараах merchant secret-үүдийг нэмнэ.

| Төрөл  | Нэр                          | Утга                                         |
| ------ | ---------------------------- | -------------------------------------------- |
| Secret | `QPAY_MERCHANT_ACCOUNT_ID`   | QPay sandbox merchant account ID             |
| Secret | `QPAY_CLIENT_ID`             | QPay sandbox client ID                       |
| Secret | `QPAY_CLIENT_SECRET`         | QPay sandbox client secret                   |
| Secret | `QPAY_INVOICE_CODE`          | QPay sandbox invoice code                    |
| Secret | `BONUM_MERCHANT_ACCOUNT_ID`  | Bonum sandbox merchant account ID            |
| Secret | `BONUM_APP_SECRET`           | Bonum sandbox app secret                     |
| Secret | `BONUM_TERMINAL_ID`          | Bonum sandbox terminal ID                    |
| Secret | `BONUM_WEBHOOK_CHECKSUM_KEY` | Bonum webhook гарын үсэг шалгах нууц түлхүүр |

`MONGOLGPT_PAYMENT_PLAN_CATALOG` жишээ:

```json
{
  "basic": { "label": "Basic", "amount": 29900 },
  "pro": { "label": "Pro", "amount": 79900 },
  "max": { "label": "Max", "amount": 199900 }
}
```

Үнэ нь бүхэл MNT дүн байна. Энэ жишээг шууд production үнэ гэж үзэхгүй; өртөг, quota болон gross margin судалгаагаар баталгаажуулсны дараа тохируулна.

Admin-ийг асаах environment-д дараах хоёр secret нэмнэ.

| Төрөл  | Нэр                                | Утга                                                         |
| ------ | ---------------------------------- | ------------------------------------------------------------ |
| Secret | `CLOUDFLARE_ACCESS_API_TOKEN`      | Зөвхөн Access application үүсгэх тусгай Cloudflare API token |
| Secret | `MONGOLGPT_ADMIN_BOOTSTRAP_EMAILS` | Админы зөвшөөрөгдсөн имэйлүүд; таслал эсвэл шинэ мөрөөр      |

`CLOUDFLARE_ACCESS_API_TOKEN`-ийг Cloudflare-ийн **My Profile → API Tokens → Create Custom Token** хэсэгт дараах хамгийн бага эрхээр үүсгэнэ.

| Хамрах хүрээ | Үйлчилгээ                                               | Эрх  |
| ------------ | ------------------------------------------------------- | ---- |
| Account      | Access: Apps and Policies                               | Edit |
| Account      | Access: Organizations, Identity Providers, and Groups   | Edit |
| Resources    | Include → MongolGPT байрлаж буй ганц Cloudflare account |      |

Zone permission, DNS edit, Worker edit, D1, R2 болон KV эрх энэ тусгай token-д хэрэггүй. Ерөнхий `CLOUDFLARE_API_TOKEN`-оос тусад нь хадгална. Access token нь SST config ажиллах үед л ашиглагдах бөгөөд admin Worker-т resource, environment variable эсвэл secret хэлбэрээр холбогдохгүй.

Cloudflare Zero Trust-ийг тухайн account дээр нэг удаа эхлүүлж, team domain болон дор хаяж нэг login method/identity provider-ийг идэвхжүүлсэн байна. Үүний дараа IaC нь:

- organization-ийн одоогийн бүх тохиргоог GET-ээр авч хадгалан, Independent MFA-д TOTP, biometrics, security key аргыг idempotent PUT-ээр нэмнэ;
- global MFA-г бусад application-д хүчээр шаардахгүй бөгөөд stack устахад organization MFA-г автоматаар сулруулахгүй;
- `admin.<stage-domain>` self-hosted Access application үүсгэнэ;
- зөвхөн `MONGOLGPT_ADMIN_BOOTSTRAP_EMAILS`-ийн имэйлүүдийг allow хийнэ;
- application болон policy түвшинд independent MFA шаардана;
- Access audience болон team domain-ийг Cloudflare-аас автоматаар авч Worker-т холбоно;
- HttpOnly, SameSite Strict болон binding cookie хамгаалалтыг асаана.

`MONGOLGPT_ADMIN_ACCESS_TEAM_DOMAIN`, `MONGOLGPT_ADMIN_ACCESS_AUDIENCE`, `MONGOLGPT_ADMIN_MFA_ENFORCED` гэсэн гар тохиргоо ашиглахгүй. `everyone` болон `bypass` policy үүсгэхгүй.

Workflow нь secret-гүй verify job-ийг эхэлж ажиллуулаад, зөвхөн `main` revision болон сонгосон GitHub Environment-д deploy job нээнэ. Access token нь зөвхөн admin асаалттай deploy-д, merchant credential нь зөвхөн төлбөр асаалттай deploy-ийн SST secret sync-д ашиглагдана. Deploy step эдгээр утгыг command argument-д гаргалгүй stdin-аар тухайн SST stage-ийн encrypted secret store-д шинэчилсний дараа deploy хийнэ. GitHub Environment-ийн deployment branch дүрмийг `main`-ээр хязгаарлана. Иймээс нууц утгыг repository файл, command history эсвэл SST placeholder-д бичихгүй. `deploy:preflight` нь OAuth, session, plan/quota, Free Auto JSON, QPay/Bonum catalog ба credential, Access-ийн organization/login method/application жагсаалтыг Cloudflare resource үүсгэхээс өмнө шалгана. Энэ нь side effect-гүй Read шалгалт тул token-ийн Edit эрхийг ялгаж нотлохгүй; organization MFA PUT болон Access application create нь deploy дотор Edit эрхийг fail-closed байдлаар бодитоор батална.

NVIDIA API Catalog-ийн trial endpoint нь зөвхөн туршилт, үнэлгээнд зориулагдсан. Production `ZEN_MODELS` тохиргоонд `integrate.api.nvidia.com` ашиглах бол тусдаа production subscription/license-аа баталгаажуулсны дараа тухайн provider дээр `productionUseApproved: true` гэж санаатай тэмдэглэнэ. Энэ баталгаа байхгүй production deploy-ийг preflight зогсооно.

Quota service-ийн дотоод token-ийг SST deploy үеэр автоматаар үүсгэнэ. Upstash болон PlanetScale secret шаардлагагүй.

`Cloudflare deploy` workflow нь preflight, typecheck, docs/web build, SST deploy, D1 migration, URL smoke check гэсэн дарааллаар ажиллана. `payment_environment`-ийг эхлээд `disabled`, sandbox merchant бэлэн болсны дараа `sandbox` гэж сонгоно. Production үед `DEPLOY <domain>` гэсэн deploy баталгаа заавал байна. Бодит мөнгөний `production` төлбөр сонгосон бол нэмэлтээр `ENABLE REAL PAYMENTS <domain>` гэсэн яг тохирох баталгаажуулалтгүй preflight зогсоно.

`MONGOLGPT_ENABLE_ANALYTICS=true` бол зөвхөн `MONGOLGPT_ENABLE_HOSTED_SERVICES=true` үеийн deploy дээр `https://stats.<domain>` live stats сайтыг Cloudflare D1-backed орчноор хамт гаргана.

Stats сайтын мэдээллийн захидлын маягт бүртгэлийг үндсэн D1 сангийн `newsletter_subscriber` хүснэгтэд хадгална. EmailOctopus secret болон тусдаа newsletter database шаардахгүй.

Enterprise холбогдох маягтын хүсэлтийг `enterprise_inquiry` хүснэгтэд хадгална. Ингэснээр Salesforce, AWS SES эсвэл EmailOctopus түр тохируулаагүй үед ч хэрэглэгчийн хүсэлт алдагдахгүй.

## Health шалгалт

Hosted орчинд:

```txt
GET https://mgpt.mn/api/health
GET https://auth.mgpt.mn/health
GET https://pay.mgpt.mn/health
```

Үндсэн үйлчилгээ амжилттай үед `status` талбар `ok` байна. Төлбөр унтраалттай deploy-д payment health нь `disabled`, sandbox/production төлбөр асаалттай үед QPay, Bonum, plan catalog, checkout болон cancellation бүгд бэлэн байж `ok` болно. Аль нэг нь дутуу бол `degraded` тул smoke deploy-ийг амжилттай гэж үзэхгүй. Health endpoint нь нууц утга, database мэдээлэл, хувилбарын дотоод дугаар задруулахгүй.

## Буцаах

1. Асуудалтай deploy-оос өмнөх баталгаатай Git commit-ийг сонгоно.
2. Тухайн commit-оос ижил stage руу `bun sst deploy --stage=<stage>` ажиллуулна.
3. `bun run deploy:smoke -- <stage>` ажиллуулж бүх нийтэд нээлттэй URL-ийг шалгана.
4. Өгөгдлийн migration орсон бол кодыг дангаар буцаахгүй; migration бүр тусдаа forward fix эсвэл урьдчилан бэлтгэсэн restore ажиллагаатай байна.

Production resource нь SST дээр хамгаалагдсан бөгөөд repository устгах эсвэл stage арилгах үйлдлээр санамсаргүй устахгүй.

## Cloudflare тасалдсан үед

Cloudflare Dashboard нээгдэхгүй бол DNS болон нууц үгийг олон дахин өөрчлөхөөс өмнө [Cloudflare Status](https://www.cloudflarestatus.com/) болон [status API](https://www.cloudflarestatus.com/api/v2/status.json)-г шалгана. Dashboard тасарсан үед local хөгжүүлэлт, test, build болон GitHub configuration бэлтгэх ажлаа үргэлжлүүлж болно; deploy-г үйлчилгээ хэвийн болтол түр хүлээнэ.
