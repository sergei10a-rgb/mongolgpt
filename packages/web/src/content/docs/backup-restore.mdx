---

MongolGPT-ийн аккаунт, ажлын талбар, захиалга, төлбөр, хэрэглээ болон аудитын өгөгдөл D1-д хадгалагдана. Нөөцлөлт нь хоёр давхар хамгаалалттай:

1. Cloudflare D1 Time Travel нь төлөвлөгөөнөөс хамаарч сүүлийн 7 эсвэл 30 хоногийн цэг рүү буцаана.
2. Cloudflare Workflow нь өдөр бүр `00:20 UTC` буюу Улаанбаатарын цагаар `08:20`-д D1-ийн SQL экспорт үүсгэж, нийтэд нээлтгүй `D1Backups` R2 санд хадгална.

R2-ийн хадгалалтын мөчлөг нь `d1/` угтвартай объектыг 90 хоногийн дараа устгаж, 24 цагаас удаан дуусаагүй олон хэсэгт байршуулалтыг цэвэрлэнэ. Санд нийтийн домэйн болон нэргүй хандалт бүү холбо.

:::caution[Үйлдвэрлэлийн орчинд сэргээх эрх]
Сэргээх ажиллагаа нь одоогийн D1 өгөгдлийг өөрчилдөг, буцаахад хүндрэлтэй үйлдэл. Засвар үйлчилгээний горим, одоогийн төлөвийн тэмдэглэгээ ба нөөц, яг тохирох баталгаажуулалт, хариуцсан хүний зөвшөөрөлгүйгээр үйлдвэрлэлийн орчны сэргээх ажиллагааг бүү эхлүүл.
:::

## Нөөцлөлтийн токен

Cloudflare-ийн **My Profile → API Tokens → Create Custom Token** хэсэгт тусдаа токен үүсгэнэ.

| Хамрах хүрээ        | Үйлчилгээ                                      | Эрх            |
| ------------------- | ---------------------------------------------- | -------------- |
| Аккаунт (`Account`) | D1                                             | Засах (`Edit`) |
| Нөөц (`Resources`)  | `Include` → MongolGPT байрлаж буй ганц аккаунт |                |

Бүс, DNS, Worker, R2, Access болон аккаунтын хэмжээнд үйлчлэх нэмэлт эрх өгөхгүй. Токеныг GitHub-ийн `dev` болон `production` орчин бүрд `D1_BACKUP_API_TOKEN` нууц утгаар хадгална. Код, бүртгэл, дэлгэцийн зураг, асуудлын бүртгэл эсвэл терминалын түүхэд утгыг нь бүү оруул.

## Өдөр тутмын шалгалт

Байршуулсны дараа дараахыг шалгана.

1. Cloudflare Workflows дотор `D1BackupWorkflow` ажиллагаа амжилттай дууссан байна.
2. Нийтэд нээлтгүй R2 санд `d1/<stage>/YYYY/MM/DD/<timestamp>-<filename>.sql` объект үүссэн байна.
3. Объектын хэмжээ 0-ээс их, нэмэлт мэдээлэл дэх `source` нь `cloudflare-d1-export`, `stage` нь зөв байна.
4. Хадгалалтын дүрэм 90 хоног, олон хэсэгт байршуулалтын цэвэрлэгээ 24 цаг гэж харагдана.
5. Ажлын урсгалын бүртгэлд токен, гарын үсэгтэй URL эсвэл SQL агуулга гараагүй байна.

D1 экспорт ажиллах богино хугацаанд өгөгдлийн сангийн хүсэлт саатаж болдог тул нөөцлөлтийг ачаалал багатай цагт ажиллуулна. Ажлын урсгал экспортыг дуусах хүртэл хязгаартай давтан оролдлогоор төлвийг шалгана. Амжилтгүй ажиллагааг алгасалгүй шалгана.

## Сүүлийн 7 эсвэл 30 хоногийн төлвөөс сэргээх

Cloudflare D1 Time Travel ашиглахдаа:

1. Ослын тасалбар нээж, шалтгаан, орчин, зорьж буй огноо цаг эсвэл төлвийн тэмдэглэгээг бүртгэнэ.
2. Бичих урсгалыг засвар үйлчилгээний горимд оруулж, төлбөрийн webhook болон арын дарааллыг түр зогсооно.
3. Одоогийн төлвийн тэмдэглэгээг авч, хүсэлтээр үүсгэсэн шинэ экспортыг нийтэд нээлтгүй R2 санд бүрэн хадгалсныг батална.
4. Сэргээх цэгийн өмнөх болон дараах өгөгдлийн шилжилтийн хувилбар, аккаунт, төлбөр, аудитын хүснэгтийн хүлээгдэж буй төлвийг шалгана.
5. Баталгаажуулалтыг `RESTORE D1 <stage> <timestamp-or-bookmark>` хэлбэрээр яг бичүүлж, хариуцсан хүний зөвшөөрөл авна.
6. Cloudflare-ийн Time Travel сэргээх ажиллагааг ажиллуулна. Буцаалтын төлвийн тэмдэглэгээг тусад нь хадгална.
7. Өгөгдлийн шилжилтийн төлөв, аккаунтын нэвтрэлт, захиалга, төлбөрийн дэвтэр, хэрэглээ ба хязгаар, админы аудит болон бэлэн байдлын суурь шалгалтыг хийсний дараа дараалал ба бичих урсгалыг нээнэ.

Сэргээх ажиллагаа буруу бол Cloudflare-ийн буцаалтын төлвийн тэмдэглэгээг ашиглан өмнөх төлөв рүү дахин сэргээж болно. Баталгаажуулалтгүй автомат үйлдвэрлэлийн сэргээх урсгал бүү үүсгэ.

## 90 хоногийн R2 экспортоос сэргээх

Урт хугацааны SQL нөөцийг шууд үйлдвэрлэлийн D1 сан руу импортлохгүй.

1. R2 объектын түлхүүр, хэмжээ, ETag, огноо болон орчныг ослын тасалбарт тэмдэглэнэ.
2. SQL экспортыг хандалтын хяналттай түр хавтас руу татаж, шалгалтын дараа устгах SQLite өгөгдлийн санд уншуулна.

```bash
sqlite3 restore-check.db < backup.sql
sqlite3 restore-check.db "PRAGMA integrity_check;"
```

3. `integrity_check` нь `ok` үр дүнтэй, өгөгдлийн шилжилтийн хүснэгт болон зайлшгүй схем, мөрийн тоо зөв эсэхийг шалгана.
4. Нууц болон хэрэглэгчийн өгөгдөл агуулсан түр файлыг шифрлэж, хандалтыг хязгаарлан, шалгалтын дараа хадгалалтын бодлогын дагуу устгана.
5. Одоогийн үйлдвэрлэлийн төлвийн тэмдэглэгээ болон хүсэлтээр үүсгэх экспортыг эхэлж авна.
6. Засвар үйлчилгээний горим, дарааллыг түр зогсоох ажиллагаа, `RESTORE D1 production <backup-key>` гэсэн яг тохирох баталгаажуулалт, эзэмшигчийн эцсийн зөвшөөрлийг авна.
7. Cloudflare D1-д импорт хийж, өгөгдлийн шилжилт болон бүх суурь ба төгсгөлөөс төгсгөл хүртэлх шалгалтыг давуулсны дараа урсгалыг нээнэ.

## Сэргээх туршилт

Үйлдвэрлэлийн бус тусдаа өгөгдлийн санд улирал тутам сэргээх туршилт хийнэ. Сүүлчийн нөөцийг сэргээж, бүрэн бүтэн байдал, өгөгдлийн шилжилт, нэвтрэлт, захиалга ба төлбөрийн дэвтэр, хэрэглээний хязгаар, админы аудитын шалгалтыг ажиллуулаад сэргээх хугацаа болон алдааг тэмдэглэнэ. Үйлдвэрлэлийн нөөцийг хөгжүүлэгчийн компьютерт удаан хадгалахгүй.

Аккаунтаа устгуулсан хэрэглэгчийн өгөгдөл идэвхтэй D1 сангаас бодлогын дагуу устах буюу санхүүгийн баримтад нэргүйжүүлэгдэнэ. Нөөц дэх хуучин хуулбар 90 хоногийн хадгалалтын мөчлөг дуусахад автоматаар устаж, сэргээсний дараа устгалын тэмдэглэгээ болон хадгалалтын ажил дахин хэрэгжинэ.
